## Abstract

Our capstone project investigates how lunar imagery can support terrain reconstruction and rover-navigation evaluation. My work has focused on preparing image information and developing the reconstruction portion of that workflow. I first generated SAM2 masks for the team's backup pipeline. At my advisor's request, I then used Astra as a development tool to construct a more robust reconstruction pipeline using the available Chandrayaan-3 imagery and calibration records. The resulting implementation performs stereo reconstruction, conservative filtering, local meshing, and registration where observations provide sufficient overlap. Recorded experiments produced 50 filtered local reconstructions from 56 candidate observations, with approximately 4.97 million per-frame points and six registered components. Numerical tests, consistency checks, export inspection, and baseline reproduction support the implementation within defined limits. However, missing calibration units, uncertain motion between exposures, and incomplete terrain coverage prevent certification of the outputs as metric, simulator-ready terrain. This report explains my contribution, the evidence supporting current progress, and the next steps needed to connect reconstruction to the team's navigation work.

## 2. Initial work: SAM2 masks for the backup pipeline

My first contribution was SAM2 mask generation for the team's backup pipeline. The original feature-processing plan included SAM/SAM2 labeling, human classification, conversion to YOLO labels, and YOLOv8 training. Following advisor feedback to keep feature detection simple, I pivoted to generating masks with SAM2. The September 23 update documents this change and reports a practical limitation: crater-like regions were being segmented, but small rocks were difficult to mask because they blended into the surrounding terrain. The slides mention Jetson Orin Nano setup, but they do not establish completed deployment or performance measurements on that device.

The saved script uses the SAM2.1 Hiera Tiny checkpoint and automatic mask generation [2], rather than a recorded set of manually supplied point prompts. Its configuration samples 16 points per side in batches of eight, with a predicted-IoU threshold of 0.8 and stability threshold of 0.95. Additional crop layers and optional model postprocessing are disabled. A subsequent area check discards masks smaller than 25 pixels. These are the settings in the current script; the output folders do not include per-run configuration hashes proving that every saved mask was generated with this exact revision.

The workflow recursively reads images and preserves their camera-family directory structure in the output. Each retained mask is saved as a full-resolution binary PNG. A preview displays mask boundaries and identifiers, and a CSV records image identity, camera family, mask identifier, pixel centroid, bounding box, area, predicted IoU, and stability score. The CSV also reserves a class field for human classification. The script skips images with an existing labels file to preserve annotations, although the existence of that file alone is not a complete processing-integrity check.

A September 30 audit of the saved outputs found 224 image folders, 224 previews, and 843 retained mask records. Six images had no retained masks. The input contains 56 images in each of four categories: calibrated left, calibrated right, raw left, and raw right. These are multiple products and views of the archive, not 224 independent scenes. All 843 class fields were blank. Thus, the saved deliverable demonstrates automatic region proposals and image-space measurements; it does not demonstrate completed rock/crater classification or a validated feature-count histogram.

The audit also reopened all 843 referenced masks. Each was binary, matched its recorded dimensions, and agreed with the CSV area, bounding box, and centroid. This verifies file and metadata consistency. It does not determine whether each region corresponds to a real rock or crater. The model's predicted IoU and stability scores are filtering signals, not accuracy measured against lunar ground truth. Evaluating small-rock recall and boundary quality still requires human-reviewed reference annotations.

The intended next connection is to associate verified feature masks with reliable stereo geometry, allowing image regions to contribute to terrain statistics. Pixel area alone cannot provide rock size in meters, and overlapping masks or repeated views cannot be counted as distinct objects without further processing. The evaluated reconstruction runs currently use intensity and geometric-support masks, not an established integration of these SAM2 outputs. The backup segmentation work and the reconstruction results therefore remain distinct deliverables.

## 3. Dataset investigation and reconstruction assumptions

The reconstruction repository contains 56 candidate observations, each represented by raw and radiometrically calibrated left and right images, for 224 images total. Each image is 1024 by 1024 pixels and contains 8-bit monochrome data [3]. The technical record documents an inventory of filenames, hashes, acquisition times, calibration files, and available metadata. This establishes what information the pipeline actually has before any geometric interpretation is attempted.

The rolling slides characterize the archive as sparse still imagery rather than continuous video: the observations span August 23 through September 2, 2023, with a reported median gap of 3 hours 24 minutes between jobs. They also identify a separate 33-frame monocular Rover Imager archive without supplied stereo calibration; that is a team-reported inventory, not an input to the reconstruction evaluated here. The slides list 55 raw right images, while the reconstruction record and current SAM2 inventory contain 56. These version-specific counts need reconciliation rather than silent substitution.

The investigation identified several limitations that affect reconstruction. Individual image XML labels are missing, and the available documentation does not provide a complete per-image pose stream. Repeated mobility identifiers are not sufficient to identify a unique acquisition. Duplicate image content also appears in the archive, so the number of files cannot be interpreted as the number of independent geometric observations. Raw images include severe saturation, shadows, glare, and row discontinuities. These conditions limit recoverable information even when processing completes successfully.

Acquisition timing is particularly significant. Candidate left and right images are separated by approximately 30–43 seconds. The supplied fixed camera geometry can be used for these exposures only under a stationary-rig assumption. Good image alignment can support parts of that assumption, but it cannot exclude every possible motion. In particular, translation parallel to the camera baseline can change depth scale without producing a corresponding vertical epipolar error. The timing investigation therefore identifies a physical uncertainty that cannot be eliminated simply by improving the matcher.

The archive supplies CAHV camera models, which encode camera centers and projection vectors [3, Appendix H]. Their center separation is approximately 242.059 in the source length units. The available records do not establish a conversion from those units to meters or a sufficiently documented reference frame. The reconstruction therefore retains calibration units throughout processing. Assuming a familiar rover-camera baseline would produce numerical meter values, but it would not establish that those values are physically correct.

These findings change the meaning of the reconstruction milestone. Producing three-dimensional points is feasible with the supplied models; certifying the points as accurately scaled lunar terrain requires additional evidence. Documenting that boundary is a substantive outcome of the work, because it prevents unresolved assumptions from being passed silently into navigation experiments.

## 4. Reconstruction pipeline and experimental development

The pipeline follows a conventional stereo sequence: camera-model interpretation, image rectification, disparity estimation, depth calculation, filtering, point-cloud export, and local meshing. It then attempts registration between observations with sufficient shared features. Original imagery remains unchanged, while run directories preserve configurations, intermediate arrays, masks, metrics, and provenance.

Camera projection is derived from the supplied CAHV parameters. Rectification transforms the two images into a common viewing geometry so that corresponding scene points should lie on approximately the same image row [4]. For rectified focal length f, baseline B, and disparity d, axial depth follows Z = fB/d [5]. Because B remains in calibration units, Z does as well. Axial depth is distance along the rectified camera's forward direction; it is not automatically terrain elevation relative to gravity.

Dense matching uses OpenCV's StereoSGBM implementation [6]. Several recorded experiments compare raw imagery, archived radiometrically calibrated imagery, and contrast enhancement. On observation 003, the initial raw run retained 123,115 points, while the corresponding calibrated run retained 148,250. Contrast enhancement retained 129,904. These comparisons show differences in coverage, but increased point count alone does not establish improved accuracy. In particular, radiometric processing can obscure the appearance of clipped raw pixels without restoring information lost during acquisition.

The original 256-disparity search truncated nearby terrain. A wider 512-disparity search recovered additional support, while explicit source-coordinate checks prevented padded image regions from being accepted as real observations. For observation 029, the raw baseline retained 99,390 points; the wider raw experiment retained 134,544. The wider calibrated experiment retained 163,945 before the subsequent conservative filtering stages. These experiments document why a single successful run was insufficient to characterize the pipeline.

Reliability checks compare left-to-right and right-to-left disparities and reject pixels that disagree by more than one pixel. Additional masks exclude unreliable raw intensity regions and weak texture. Final filtering removes unsupported borders, isolated regions, and neighborhoods with inconsistent disparity. This trades coverage for stronger local support. It can also remove genuine small rocks or narrow terrain features, so the filtered output should not be interpreted as a complete obstacle inventory.

Local meshing connects nearby supported samples while rejecting triangles that cross excessive depth changes or long edges. It does not fill gaps with generated surfaces. This preserves a useful distinction between terrain supported by observations and terrain that would have to be inferred. The resulting meshes are partial surfaces; open boundaries and holes are expected consequences of the available evidence.

Registration extends reconstruction beyond individual image pairs. Feature correspondences and source stereo depth support pose estimation between candidate observations. A held-out subset of correspondences evaluates reprojection after fitting, while target stereo depth provides another consistency check. Only accepted links contribute to connected components. Disconnected observations remain separate instead of receiving invented positions in a global map.

## 5. Current results and scope of validation

The final filtered batch contains 50 local point clouds and 50 partial meshes from 56 candidate observations. It totals 4,969,574 per-frame points and 508,095 local mesh triangles, with median image coverage of 10.03%. These totals include overlapping observations. They are not counts of unique points in a single global terrain model. Six candidates were rejected because the available evidence failed the geometric or image-quality criteria.

Observation 043 illustrates the importance of rejection. Its fixed-model rectification produced a median vertical feature discrepancy of approximately 30.96 pixels despite numerous matches. The record does not resolve whether this reflects motion, misassociation, or another acquisition problem. A deliberate rejection test confirmed that the standalone reconstruction path raised the expected rejection and exported no cloud. The result demonstrates enforcement of the criterion, rather than recovery of valid geometry from that observation.

Registration tested 129 candidate links and accepted 17, producing six multi-frame components and leaving 31 observations isolated. These results establish that some local overlap supports registration, while also showing why the current archive does not support a continuous global reconstruction under the implemented criteria. The registered meshes combine existing observed triangles; they retain holes and may contain overlapping faces.

Validation addresses several distinct questions. Synthetic projection, rectification, and backprojection tests check numerical conventions. Saved results report maximum vertical round-trip error of approximately 5.68 × 10^-13 pixels and maximum three-dimensional round-trip error of 2.18 × 10^-11 calibration units. A synthetic image pair with a known 24-pixel shift returned the expected disparity signs. These small errors support implementation correctness on the constructed tests, not equivalent accuracy on lunar terrain.

Image-based checks assess internal consistency. For the supplied camera model, the median of the per-pair median rectified vertical errors was approximately 0.515 pixels, compared with 1.276 pixels when only the camera-axis vectors were normalized. This supports retaining the literal supplied projection model over that particular modification. However, neither comparison proves the physical scale or eliminates acquisition motion. Registration checks likewise evaluate consistency between observations that can share calibration biases.

Export and reproducibility checks address the reliability of the saved artifacts. The technical record reports reopening 118 PLY exports to inspect counts, finite coordinates, indices, and file lengths, with additional checks on representative triangles. It also reports unchanged hashes for all 255 original input files. A repeated baseline run reproduced the original left and right disparity, depth, and XYZ arrays exactly, including invalid-value locations. The saved reproduction record confirms agreement for all four arrays.

Together, these results support an operational and auditable reconstruction pipeline. They do not establish an absolute terrain-error bound. No surveyed reference surface, verified metric calibration, or complete acquisition-motion evidence is available in the reviewed records. The appropriate midterm claim is therefore supported local reconstruction in source calibration units, with physical certification still unresolved.

## 7. Next steps and acceptance criteria

My first priority is to resolve the physical interpretation of the calibration. The needed evidence includes a declaration of camera-center units and reference frame, individual product labels where available, and stationarity or motion information for the separated stereo exposures. Completion means documenting a justified scale conversion and the conditions under which the fixed-rig model applies. More reconstruction runs alone cannot supply these missing facts.

The next priority is external validation. After scale is established, a measured target or trusted terrain reference is needed to evaluate physical error. This evaluation should distinguish image consistency from depth accuracy and retain unsuccessful cases. Registration should also be assessed with attention to duplicate images and whether apparently repeated support provides genuinely independent geometry.

For the backup pipeline, the next step is to review and classify a representative set of SAM2 proposals, emphasizing the small rocks that the initial workflow struggled to identify. Evaluation should record missed objects, incorrect regions, boundary quality, and duplicate proposals. Only after that review should accepted masks be associated with valid stereo depth. A feature table should preserve source image, mask identity, reviewed class, pixel measurements, supported 3D measurements, units, and confidence or rejection status. This proposed interface would help Jonathan, Alejandro, and me connect feature analysis to the terrain generator without treating unverified masks as physical measurements.

For simulation handoff, I plan to work with the navigation and integration team on one selected local component. Acceptance should require a documented origin, axis convention, metric scale, gravity alignment, and supported-region representation. Visual and collision geometry need separate review. Unknown holes must remain excluded from traversal or explicitly marked unknown. Successful file import will be a compatibility check, not the final acceptance criterion.
