1. Archive Structure 
 
1.1. Mission Archive Structure 
 
At mission level, data is organized as mission id wise bundle. The mission id  (ch3-> chandrayaan-3) wise 
bundle at next level is organized based on the instrument host id (chr-> chandrayaan rover) wise bundle. 
The instrument host id  (nav->navigational camera ) bundle at next level is organized based on the 
mission phase id  (nop->normal operations phase) . Each mission phase id is having instrument id wise 
collection. Below figure shows the mission archive structure.  
 
 
1.2. Instrument Archive Structure 
 
Under each instrument wise data collection, data is organized under each directory defined by PDS4. 
Data is organized based on the levels of data processing and data products definitions. Data products is 
organized into year, month and day wise as yyyymmdd. The year month and day wise directory contains 
PDS4 data products including PDS4 Label products. Below Figures shows the detail of nav instrument

2. Data Products Description

Calibrated data products . For each payload observation, PDS4 data products are generated (based on 
product id & sensor id derived from file name (section 3)) and organized under year month day wise 
collection directory defined under instrument collection structure shown in section 1.2. Below Figure 
shows the structure of NavCam Raw and Calibrated Data Product file.

3. File Naming Conventions & Formats 
This section describes the naming convention used for science data file s for the Chandrayaan-3 mission. 
below shows the detail description about the following file naming conventions designed for the data 
products. 
ch3_<nav>_<mtc>_<YYYYMMDDTHHMMSSsss>_<p>_<prd>_<stn>_mob.fff 
Code Description 
ch3 It denotes the Mission name whose value is fixed as ch3 
nav It denotes the Instrument id whose value is fixed as nav 
m It denotes the mission phase name, it can have following value 
= e (refers to the Earth Bound Phase - ebp) 
= n (refers to the Normal Operations Phase - nop) 
t It denotes the data type; it can have following values: 
= r (it denotes raw data) 
= c (It denotes calibrated data) 
= d (It denotes derived data) 
c It denotes the imaging mode/camera id/band. It can be one of the 
following: 
= l (it denotes left camera of NavCam) 
= r (it denotes right camera of NavCam) 
YYYYMMDDTHHMMSSssss It denotes the observation/imaging start time in format 
[YYYYMMDDTHHMMSSsss] 
YYYY = stand for year 
MM = stand for month in MM format 
DD = stand for day in DD format 
T = stand for time. 
HH = stand for hour in HH format 
MM = stand for minute in MM format 
SSS = stand for seconds in SS format 
ssss = stand for nanosecond in ssss format 
p It denotes the PDS Data Products categories. It value can be any  
of the following: 
= d (It denotes data products under data directory) 
= b (it denotes browse data products under browse directory) 
= g (it denotes gridded data products under geometry directory)

prd It denotes the PDS Data Product Name. It value can be any 
of the following: 
= img (It denotes the image data product) 
= brw (It denotes the browse data product) 
= grd (It denotes the gridded data product) 
= dtm (it denotes DTM derived product) 
= oth (it denotes Ortho derived product) 
stn It denotes the station id from which data was acquired. It value 
can be any of the following: 
= d32 (ISSDC Bangalore) 
= d18 (ISSDC Bangalore) 
= gds (Gold Stone USA) 
= cnb (Canberra, Australia ) 
mob 
 
Rover mobility id given by the mission team 
fff It denotes the standard file type extension. It can have any one of  
the following values: 
= png (PDS Image Data File) 
= xml (PDS Detached Label File) 
= png (PDS Browse Data File) 
= csv (PDS Geometry Data File) 
= tif (PDS Geo tiff data)
